The `sidebar` node draws one sidebar region and renders its `children` inside it, in order.

It works in any host. A host that already mounts a sidebar provider, such as the app shell, keeps its own: the node uses that provider rather than mounting a second one. In a host without one, the node mounts its own.

## The `collapsible` key

`collapsible` is a boolean.

- `false` draws the sidebar in the page flow, at a fixed width. It does not follow the host's open state, so it is visible in every host. Every example on this page authors it.
- `true`, or leaving the key out, selects the collapsible form instead. That form is not drawn in the page flow: it is positioned against the edge of the viewport, at full viewport height, so it does not appear where the schema places it. Author `false` for a sidebar that does.

## Schema

```ts
import type { SidebarSchema } from '@object-ui/types';

const sidebar: SidebarSchema = {
  type: 'sidebar',
  collapsible: false,
  className: 'gap-1 border-r p-2',
  children: [
    { type: 'text', content: 'Menu', className: 'px-2 text-xs text-muted-foreground' },
    { type: 'button', label: 'Dashboard', variant: 'ghost', className: 'w-full justify-start' },
    { type: 'button', label: 'Settings', variant: 'ghost', className: 'w-full justify-start' },
  ],
};
```

The renderer reads `collapsible` and `children`, and passes `className` to the sidebar element.
